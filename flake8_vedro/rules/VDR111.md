# VDR111. Skipped scenarios should include a ticket in the reason
A skipped scenario without a reason, or with a reason like "temporarily disabled", is easy to forget: nobody knows why it was skipped and when it can be enabled again.
A ticket in the reason links the skip to the work that has to be done to enable the scenario.

The rule checks `@vedro.skip` and `@skip` imported from `vedro` (also with an alias). The reason can be passed both as a positional argument and as `reason=...`.

### ❌ Anti-pattern
```python
@vedro.skip
class Scenario(vedro.Scenario):
    subject = "login as registered user"


@vedro.skip(reason="temporarily disabled")
class Scenario(vedro.Scenario):
    subject = "login as registered user"
```

### ✅ Best practice
```python
@vedro.skip("CHAT-123: login is broken on staging")
class Scenario(vedro.Scenario):
    subject = "login as registered user"
```

### ⚠️ Configuration

The rule is disabled by default. Ticket format depends on the tracker, so it is configured with a regex pattern, which should be found anywhere in the reason (default: `[A-Z][A-Z0-9]+-\d+`).
You can configure this in the `setup.cfg` file using the parameters `require_skip_ticket` and `skip_ticket_pattern`:

```ini
[flake8]
require_skip_ticket = true
skip_ticket_pattern = [A-Z][A-Z0-9]+-\d+
```

### ⚠️ Exception

A reason that is not a string literal (a variable, an f-string, a function call) cannot be checked statically, so it is skipped:

```python
@vedro.skip(reason=SKIP_REASON)  # not an error
class Scenario(vedro.Scenario):
    subject = "login as registered user"
```

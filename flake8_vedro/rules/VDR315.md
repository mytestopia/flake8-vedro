# VDR315. API response status code should be asserted
An API response body can match the expected schema even if the request has failed, e.g. an error response with an empty list.
So every API response saved in "when" step should have an assertion on its status code.

### ❌ Anti-pattern
```python
from interfaces.chat_api import ChatApi


class Scenario(vedro.Scenario):
    subject = "get registered user"

    def when_user_requests_user(self):
        self.response = ChatApi().get_user(self.user)  # VDR315

    def then_it_should_return_user(self):
        assert self.response.json() == UserSchema % {
            "username": self.user["username"]
        }
```

### ✅ Best practice
```python
from interfaces.chat_api import ChatApi


class Scenario(vedro.Scenario):
    subject = "get registered user"

    def when_user_requests_user(self):
        self.response = ChatApi().get_user(self.user)

    def then_it_should_return_success_status_code(self):
        assert self.response.status_code == 200

    def and_it_should_return_user(self):
        assert self.response.json() == UserSchema % {
            "username": self.user["username"]
        }
```

### ⚠️ Configuration

The rule is disabled by default. To enable it, list API interfaces in the `setup.cfg` file using the parameter `api_interfaces_list`:

```ini
[flake8]
api_interfaces_list = ChatApi,SmthApi
```

Only interfaces imported from `interfaces` folder are checked. This list is not related to `allowed_interfaces_list` (VDR302), which lists interfaces allowed to use outside "when" step.

### ⚠️ Exception

The rule does not look into helper functions, so the response is treated as checked if in "then"/"and"/"but" steps:
- a function starting with `assert`, `check`, `verify`, `validate` or `ensure` is called;
- the response is passed to any function, e.g. `response_is_valid(self.response)`.

Only responses saved into a variable or a scope variable are checked. A value derived from the response, e.g. `ChatApi().get_user().json()`, is not a response.

If assertion steps do not have any `assert`, the rule is skipped: it is reported by VDR307.

# VDR314. Steps should not have branching
Branching (`if`, `match-case`, ternary expressions) inside scenario steps makes tests unpredictable. Each scenario should follow a single execution path.

If you need different behavior depending on conditions, create separated or parametrized scenarios instead.

### ❌ Anti-pattern
```python
class Scenario(vedro.Scenario):
    subject = "login as registered user"

    def given_user(self):
        self.user = fake(NewUserSchema)

    def given_registered_user(self):
        registered_user(self.user)

    def when_user_logins(self):
        self.response = httpx.post(f"{API_URL}/auth/login", json=self.user)

    def then_it_should_return_success_status_code(self):
        # This is hard to understand what exactly we are expecting in scenario
        if self.response.status_code == 200:
            assert self.response.json()["token"] is not None
        else:
            assert self.response.json()["error"] is not None
```

### ✅ Best practice
```python
class Scenario(vedro.Scenario):
    subject = "login as registered user"

    def given_user(self):
        self.user = fake(NewUserSchema)

    def given_registered_user(self):
        registered_user(self.user)

    def when_user_logins(self):
        self.response = httpx.post(f"{API_URL}/auth/login", json=self.user)

    def then_it_should_return_success_status_code(self):
        assert self.response.status_code == 200

    def then_it_should_return_token(self):
        assert self.response.json()["token"] is not None
```
